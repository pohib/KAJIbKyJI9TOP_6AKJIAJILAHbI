## 3. Анализ уязвимостей Z

### 3.1. `msgpack` (High)

**CVE-2026-114613:** утечка памяти при десериализации map => дудосик (dos) и ddos косвенно.
**GHSA-6v7p-g79w-8964:** out-of-bounds read при повторном использовании `Unpacker` после ошибки => дудос и веб-атаки на приложение(SQLi, XSS, CSRF и ).

**Влияние на проект:** низкое. Апишка **не использует `msgpack` напрямую**. Пакет является транзитивной зависимостью (вероятно, через `fastapi` или через кеш `pip`).

**Рекомендация:** найти родительский пакет и обновить его. Проверить:
```bash
docker run --rm calcapi:scan pip show msgpack
```

### 3.2. `urllib3` (High (2), Medium)

**CVE-2026-97687:** перехват трафика через HTTPS-прокси (некорректная изоляция TLS-контекста).
**CVE-2026-97689:** неограниченный рост памяти в chunk-парсере => DoS.
**CVE-2026-97688:** бесконечный цикл при декодировании Deflate в chunked-ответе => переполнение ресурса CPU.

**Влияние на проект:** низкое. Апишка баклажанов не делает исходящих HTTP-запросов через прокси. `urllib3` тянется транзитивно (через `pip`/`requests`/`httpx`).

**Рекомендация:** обновить `pip` до последней версии, удалить `requests`/`httpx` из прод-образа. Проверить:
```bash
docker run --rm calcapi:scan pip show urllib3
```

### 3.3. `setuptools` (High, Medium, Low)

**CVE-2025-47273:** path traversal в `PackageIndex` => потенциальный RCE при установке пакетов из недоверенного источника.
**CVE-2026-59890:** обход `MANIFEST.in` через Unicode-нормализацию (только macOS).
**CVE-2026-59892:** Экранирование в путях винды при установке propagator-jaeger (только Windows).

**Влияние на проект:** **нулевое в рантайме**. `setuptools` нужен только для сборки (`pip install .`). После сборки он не используется.

**Рекомендация:** обновить `setuptools` **до** установки зависимостей в `Dockerfile`:
```dockerfile
RUN pip install --no-cache-dir --upgrade pip setuptools \
 && pip install --no-cache-dir -r requirements.txt
```

Если Trivy будет все еще видеть уязы, то пересобрать образ с `--no-cache` (Docker кеширует слой `pip install`).

## 5. Предложения по улучшению

### 5.1. Безопасность образа

- [ ] **Перейти на distroless base** (`gcr.io/distroless/python3-debian12`). Убирает `bash`, `perl`, `tar`, `ncurses`, `util-linux` — сокращает список CVE.
- [ ] **Multi-stage build**: отделить build-time (`pip install`) от runtime. В финальный образ не попадут `setuptools` и временные `.whl`.
- [ ] **Подпись образа через cosign / sigstore** для защиты цепочки поставок.

### 5.2. Безопасность зависимостей

- [ ] **`pip-audit`** в CI: дополнительная проверка `requirements.txt` на CVE.
- [ ] **`requirements.lock`** через `pip-compile` для детерминированных сборок.

### 5.3. Безопасность кода

- [ ] Убрать `try/except Exception` в `health.py`: заменить на конкретные исключения (осознанно оставлен с `# noqa: BLE001`).
- [ ] Ужесточить валидацию `a` и `b` (ограничить разумным диапазоном, например `[-1e15, 1e15]`), чтобы избежать `inf`/`nan`.
- [ ] Добавить rate limiting (от медленных запросов, брутфорсика).

### 5.4. Безопасность CI/CD

- [ ] **Branch protection**: обязательное прохождение CI перед merge в `main`.
- [ ] **Gitleaks** для поиска секретов в коммитах.
- [ ] **Checkov** для сканирования workflow-файлов.

### 5.5. Мониторинг

- [ ] Логирование ошибок с `request-id` (для трассировки).
- [ ] Алерты на аномалии в `/health` (Prometheus + Grafana).

## 7. Принятые риски (unreachable)

Уязвимости в системных пакетах базового образа `python:3.13-slim` (Debian 13): `glibc`, `util-linux`, `perl`, `ncurses`, `coreutils`, `tar`, `zlib` **не эксплуатируются** в сценарии.

- API **не вызывает** `subprocess`, `os.system`, `perl`, `tar`, `mount`, `nsenter`.
- Контейнер работает **под non-root** (`appuser`).
- `/calculate` и `/health` — чистые функции без shell-вызовов.
- Все входные данные валидируются через Pydantic.

Эти CVE **требуют локального вызова** соответствующей утилиты васяном (злоумышленником), что в данном контейнере невозможно. Приняты как **unreachable**.
